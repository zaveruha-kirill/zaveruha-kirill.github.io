Проблема

Антон — владелец сервисного центра по ремонту телефонов и ноутбуков. Все заявки вёл в Excel-таблице: дата приёма, модель, проблема, статус. Казалось бы, работает. Но на деле — хаос.

Клиенты звонили по 3–4 раза, чтобы узнать статус. Мастера не всегда обновляли таблицу. Квитанции печатались вручную в Word. О том, что ремонт закончен, клиенту звонили тогда, когда вспоминали. Один из трёх заказов задерживался на 2+ дня только из-за неразберихи в коммуникации.

Задача

Построить систему, где мастер видит только свои задачи, менеджер видит все заявки с фильтрами, клиент получает SMS о смене статуса автоматически, а квитанция формируется за 10 секунд нажатием кнопки.

Решение

Разработал кастомную CRM на Next.js с PostgreSQL и деплоем через Docker Compose. Антон поднял систему на VPS одной командой — без системного администратора.

Ключевые модули:

  • Приём устройства: форма с клиентом, типом устройства, описанием проблемы и предварительной стоимостью
  • Статусы заявки: НОВАЯ → ДИАГНОСТИКА → ОЖИДАНИЕ ЗАПЧАСТЕЙ → ГОТОВА → ВЫДАНА — каждый переход логируется
  • PDF-квитанция: генерируется автоматически при приёме, отправляется клиенту на email
  • Уведомления: SMS клиенту при смене статуса (интеграция с SMS-провайдером)
  • Складской учёт: расход запчастей на заявку, остатки по позициям
  • Система ролей: ADMIN (всё), MANAGER (заявки без настроек), EMPLOYEE (только свои заявки)

Технический стек

  • Next.js 14 + TypeScript — фронтенд и API routes
  • Prisma + PostgreSQL — база данных
  • NextAuth.js — авторизация с ролями
  • React PDF — генерация квитанций на сервере
  • Docker Compose — деплой на VPS

Результат

Через месяц после запуска Антон прислал сообщение: «Кирилл, я не могу поверить, но клиенты перестали звонить с вопросом "как там мой телефон". СМС приходит само — люди просто ждут». Время закрытия средней заявки сократилось с 5 до 3 рабочих дней. Звонков о статусе стало на 70% меньше.

Сейчас на системе работают 3 мастера и 1 менеджер. Антон думает о продаже лицензии другим сервисным центрам.
